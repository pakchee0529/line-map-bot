# LINE Bot 検索アップデート計画

更新日: 2026-07-29

## 1. 結論

- `木ノ原40E1S3～40E1S4` は、ローカルの LINE Bot と PC 版の双方で若番・老番を解決できる。
- `GPS.json` は両リポジトリで件数と SHA-256 が一致している。
- したがって、LINE 上で応答が返らない直接原因は GPS データ欠落ではなく、公開中コードの版ずれ、Webhook の実行状態、または公開環境設定のいずれかを先に疑う。
- PC 版の検索改善は再利用できる。ただし PySide6 の UI を移すのではなく、純粋な検索ロジックと結果契約だけを LINE Bot へ移植する。
- 検索エンジン更新と地番図レイヤー公開は別リリースにする。

## 2. 現状差分

### LINE Bot に既にあるもの

- NFKC、英字大文字化、半角・全角スペース除去
- `～` / `~` の径間分割
- 後半の冠称名省略補完
- W / N / E / S / G / K 枝番の解析
- 完全一致、近い枝番、枝番縮退、近い親番号の探索
- 2 点が解決できた径間のマルチピン地図
- 複数行入力、位置情報から半径 200 m 検索
- Redis を使う複数地点地図

### PC 版にあり、LINE Bot に不足するもの

1. 若番・老番それぞれの解決結果を保持する `span_points`
2. `出谷49G1 -> 出谷49G1G9` のような末尾 G9 補正
3. K 枝番を仮想柱候補として示す警告
4. G9 を危険傾斜地等の補正候補として示す警告
5. 採用候補と採用理由の一覧
6. 未解決時の同一冠称名候補
7. 冠称名だけの検索と、その冠称内の電柱・概略線表示
8. 同一 GPS 名の重複座標・異座標の品質警告
9. 市町村情報を添えた結果表示
10. 空間インデックスを使った周辺検索

### PC 固有で、そのままは移さないもの

- PySide6 の画面、WebChannel、起動時の奈良県全域表示
- KML 保存、Google Earth Pro 起動
- A4 現場地図生成
- オフライン地図資産

これらは検索結果を利用する別機能であり、LINE Bot の検索コアへ混ぜない。

## 3. 共通化する境界

検索コアの入出力を次で固定する。

入力:

- 利用者が入力した 1 行
- 正規化済み GPS 辞書

出力:

- `found`
- `display_name`
- `front_key` / `back_key`
- `adopted`
- `span_points`
- `suggestions`
- `suggestion_details`
- `warnings`
- `candidate_notes`
- `resolution_kind`

検索コアは URL、LINE メッセージ、Qt Widget、Redis、Supabase を扱わない。

LINE 側は結果を次へ変換する。

- 1 点: Google Maps
- 2 点: 2 点地図 URL
- 複数行: マルチピン地図
- 未解決: 候補と理由を短文で返信
- 冠称名のみ: 冠称内地図への導線

PC 側は現在の Qt、Leaflet、Street View、Earth、現場地図生成を維持する。

## 4. 段階実装

### Phase 0: 公開環境の現在地確認

- 公開中コミット識別子、GPS データ SHA、検索エンジン版を確認できる read-only health 情報を追加する。
- Webhook の受信、署名検証、返信 API、例外のどこで停止したかを区別する。
- 座標や利用者 ID は診断ログへ出さない。

完了条件:

- `木ノ原40E1S3～40E1S4` が無応答になった場合、公開版の版ずれか実行エラーかを判定できる。

### Phase 1: 検索コアの同期

- PC 版 `app/core/search.py` 相当を LINE Bot の独立モジュールへ移す。
- URL生成と返信整形は LINE 側へ残す。
- 現在の LINE 検索を `v1`、新検索を `v2` とし、環境変数で切り替え可能にする。

完了条件:

- 既存の正常検索結果を壊さない。
- G9、K、冠称省略、2 点、片点、未解決候補を構造化結果で返せる。

### Phase 2: 実データ回帰試験

最低限、次を固定ケースにする。

- `木ノ原40E1S3～40E1S4`
- `西川95G9～95G1G9`
- `出谷49G1`
- `西川118G1G9`
- K 枝番
- 後半冠称省略、後半冠称あり
- 半角・全角スペース、`～`、`~`
- 若番のみ存在、老番のみ存在、両方存在、両方不存在
- 複数行入力
- 引込を含む入力

旧版と新版を同じ GPS データへ当て、差分を JSON で確認する。自動採用が変わるケースは、理由を表示して人間確認する。

### Phase 3: LINE 向け表示改善

- 未解決を無言にせず、近い候補を最大 5 件返す。
- 補正採用時は「入力 -> 採用名」と理由を短く表示する。
- K / G9 は色だけに頼らず、`注意` ラベルと文言で示す。
- 2 点検索は若番・老番の両方を名称付きで表示する。
- 冠称名のみの検索は PC 版の概略線生成を流用候補とするが、実在する GPS 点だけを結び、推測線であることを明記する。

### Phase 4: 段階公開

- 管理者またはテスト用ユーザーだけ `v2` を使うカナリア期間を設ける。
- `v1` と `v2` の結果分類だけを比較し、個人情報や座標は記録しない。
- 問題がなければ既定を `v2` にする。
- 問題時は環境変数だけで `v1` に戻す。

### Phase 5: 地番図レイヤー

- 検索 `v2` の安定確認後に別リリースで有効化する。
- `CADASTRAL_LAYER_ENABLED=0` で即時無効化できる状態を維持する。
- 検索失敗時でも通常の 1 点・2 点地図は使えるようにする。

## 5. 優先順位

1. 公開版の識別と無応答原因の可視化
2. PC 版検索コアの移植と回帰試験
3. 未解決候補・警告の LINE 表示
4. 冠称名検索
5. 地番図レイヤー公開

検索と地番図を同時公開しないことを最重要の安全策とする。

## 6. 受入条件

- `木ノ原40E1S3～40E1S4` が 2 点地図として応答する。
- 完全一致した既存検索の採用地点が意図せず変わらない。
- G9 補正は理由を伴い、K は仮想柱候補として警告される。
- 未解決時にも候補または「候補なし」が返り、無応答にならない。
- 公開版の検索エンジン版、コミット、GPS データ版を秘密値なしで確認できる。
- 検索 `v2` と地番図をそれぞれ独立して無効化できる。
- LINE Bot の検索コアは PySide6、Supabase、Redis に依存しない。
